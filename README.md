# Lumière

Просмотрщик локальной видеотеки для macOS 26. Назван в честь братьев Люмьер: SwiftUI + Liquid Glass, метаданные с TMDB,
отслеживание просмотренного и позиции остановки. Без сервера — всё локально.
macOS 26, Apple Silicon. Приложение писалось под себя, но исходники открыты — забирайте.

## Установка

Готовая сборка: [последний релиз](https://github.com/shineexxx/lumiere/releases/latest) →
скачать `Lumiere-<версия>.zip`, распаковать, положить в «Программы».

Приложение подписано ad-hoc, без учётной записи разработчика. При первом запуске
macOS может сказать, что не может проверить разработчика — тогда правый клик по
приложению → «Открыть», либо:

```bash
xattr -dr com.apple.quarantine /Applications/Lumiere.app
```

Дальше приложение обновляет себя само — см. «Обновления».

## Сборка из исходников

```bash
Scripts/fetch-vlckit.sh   # VLCKit ~540 МБ, в репозитории его нет
open VideoClient.xcodeproj
```

Собрать и запустить — ⌘R. Или из терминала:

```bash
xcodebuild -project VideoClient.xcodeproj -scheme VideoClient -configuration Debug build
```

Приложение подписывается ad-hoc (`Sign to Run Locally`), команда разработчика не нужна.

## Первый запуск

1. **Настройки → TMDB** — вставьте API-ключ (бесплатный: themoviedb.org → Settings → API).
   Подходит и короткий ключ v3, и длинный токен v4. Хранится в настройках приложения.
2. **⌘O** — добавьте папку с фильмами или сериалами.
3. Приложение просканирует её, распарсит имена файлов и предложит совпадения из TMDB.
   Каждое совпадение подтверждается вручную; в настройках можно включить автоприём уверенных.

## Как устроено

```
VideoClient/
  App/        точка входа, LibraryCoordinator (сканирование + метаданные)
  Models/     MediaEntry, EpisodeEntry, VideoFileRef, WatchState
  Library/    FolderAccess (security-scoped bookmarks), сканер, парсер имён
  Store/      LibraryStore — @Observable, JSON в Application Support
  TMDB/       клиент, DTO, матчер, кэш постеров
  Player/     PlayerEngine (протокол), AVPlayerEngine, VLCPlayerEngine, PlaybackSession
  UI/         сайдбар, сетка, карточка, лист подтверждения, настройки
```

Данные лежат в `~/Library/Application Support/Lumiere/library.json`,
постеры — в `~/Library/Caches/Lumiere/Images`.

### Отслеживание просмотра

- Позиция пишется раз в секунду, на диск — с дебаунсом в 1 секунду.
- Файл считается просмотренным на **92%** длительности.
- При продолжении отматывается **8 секунд** назад.
- «Продолжить смотреть» показывает незаконченный файл, а для сериалов — следующую серию,
  если предыдущая досмотрена. Автопереход к следующей серии включён.

Пороги — в `WatchRules` (`Models/Models.swift`).

### Парсинг имён

`FilenameParser` вытаскивает название, год и `SxxExx` из релизных имён:
`S01E02`, `s1e2`, `1x05`, `Сезон 1 Серия 5`, `Season 1 Episode 5`.
Если имя файла состоит только из номера серии, название берётся из имени папки
(папки вида `Season 2` / `Сезон 2` пропускаются).

Технический хвост (качество, кодеки, релиз-группа) режется по словарю `junkTokens` —
если ваш рип называется как-то экзотично, дополните словарь.

## VLC

Воспроизведение целиком на VLCKit 4 — один движок на все контейнеры: MKV, AVI, WMV,
MPEG-TS внутри `.mp4` и прочее, что AVFoundation не открывает. AVPlayer остался в коде
запасным путём на случай, если фреймворка нет.

Фреймворк в репозитории не хранится: 543 МБ, а отдельные файлы в нём больше лимита GitHub.
Ставится скриптом:

```bash
Scripts/fetch-vlckit.sh
```

Скрипт кладёт `Frameworks/VLCKit.xcframework` — сборку VLCKit 4.0 с artifacts.videolan.org.
Без фреймворка проект тоже собирается: весь VLC-код закрыт `#if canImport(VLCKit)`,
приложение возвращается к AVPlayer и честно объясняет, если формат не открывается.

Журнал libVLC пишется в `~/Library/Logs/Lumiere/vlc.log` (предупреждения и ошибки) —
он однажды помог найти причину падения плеера.

## Синхронизация просмотренного

Отметки о просмотре и позиции синхронизируются через iCloud
(`NSUbiquitousKeyValueStore`) — включается в Настройках → Синхронизация.
Синхронизируются только отметки; файлы и папки остаются на этом Маке.
При конфликте побеждает более свежая запись, а «просмотрено» никогда
не снимается автоматически.

**Важно:** iCloud требует подписи с вашей учётной записью разработчика.
Проект собирается ad-hoc («для локального запуска»), при такой подписи
контейнер iCloud не выдаётся и сборка с этим правом падает. Чтобы включить:

1. В Xcode выберите таргет → Signing & Capabilities → свою команду.
2. Замените содержимое `VideoClient.entitlements` на `Lumiere-iCloud.entitlements`.

Без этого работает экспорт и импорт истории в файл — там же, в настройках.
Импорт сливает данные, а не заменяет их.

## Ограничения

- Сканирование пропускает файлы меньше 50 МБ (`LibraryScanner.minimumFileSize`) —
  чтобы не тащить в библиотеку сэмплы и трейлеры.
- Внешние субтитры (.srt/.ass рядом с файлом) не подключаются; встроенные в контейнер
  дорожки AVPlayer показывает сам.
- Библиотека хранится в одном JSON. Для нескольких тысяч карточек это нормально;
  для десятков тысяч имеет смысл переехать на SwiftData.

## Обновления

Приложение при запуске смотрит [GitHub Releases](https://github.com/shineexxx/lumiere/releases)
и сравнивает тег последнего релиза со своей версией.

- **Тумблер «Обновлять автоматически»** (Настройки → Обновления, включён по умолчанию):
  новая версия скачивается сама и ждёт — установка идёт только по кнопке
  «Перезапустить и обновить», чтобы не оборвать просмотр на середине.
- Тумблер выключен — приложение просто сообщает, что вышла новая версия.
- Проверить руками: меню «Lumière» → «Проверить обновления…».

Подмена бандла делается скриптом, который дожидается выхода приложения, распаковывает
новую версию поверх старой и запускает её заново. Перед установкой проверяется, что в
архиве лежит приложение с тем же идентификатором бандла.

Выпуск новой версии:

```bash
# поднять MARKETING_VERSION в проекте, затем
Scripts/release.sh "что изменилось"
```
